Where the responsibilities live

Architecture

Sources publish events. ZooGlass maintains the view. Applications decide how to present it.

A defined place for reconciliation

View definitions map source events to fields. Configured strategies decide how those contributions change the view.

Multiple views can reuse the same sources with different mappings, update rules and retained windows.

ZooGlass owns the reconciliation. A demo or application consumes its result.

Inside the runtime

From publication to maintained state

  1. ValidateCheck the envelope, source and publication identity.
  2. Apply strategiesResolve entities and apply each field’s configured rules.
  3. Commit stateInstall the view changes and recorded publication outcome together.
  4. Expose the resultReturn the receipt and make the resulting snapshot available.

A rejected whole publication installs no staged target changes. An admitted receipt can include different policy outcomes for different targets.

State that can survive a restart

Choose memory storage for transient runs or a database for durable state. ZooGlass commits view state and retained publication outcomes atomically.

Recovery validates stored state before the service becomes ready. A source retry after a lost acknowledgement can recover the retained outcome instead of repeating the effect.

Accessing the view

Applications read snapshots of the maintained view or subscribe to live updates. ZooGlass handles the field rules; the application chooses how to present the result.

Sources publish events and receive acknowledgements. Publication identities let them retry safely within the configured retention window. The API guide describes the interfaces and their contracts.

Workbench around the system

Workbench is a deterministic timeline simulator that coordinates sources, connections and checks around ZooGlass. A scenario brings the inputs, deliberate failures and expected results together in one place.

Real interfaces, observable results

Workbench sends events through source connections and checks the state exposed by ZooGlass. Expected values are assertions about the result, not a replacement for the service’s reconciliation.

Presentation stays separate

Scenarios can run with protocol clients without a browser. Demo applications add a visual explanation, and browser checks can exercise their behaviour without making a particular UI part of the core scenario runner.
