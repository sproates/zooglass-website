ZooGlass

Event-driven live views

ZooGlass maintains application views from events produced by independent systems. You define what belongs in each field and how updates should be handled. ZooGlass keeps the resulting state.

Explore the architecture →

The problem it solves

Events arrive late, arrive twice, contradict an earlier report or stop arriving altogether. Combining them into a useful view means deciding what to keep, what to change and what is no longer fresh.

Those decisions often end up scattered across application services and client code. ZooGlass gives them a defined home: configurable strategies applied as events arrive.

Your application uses the resulting view without implementing those rules itself.

What ZooGlass handles

Choose the behaviour

Keep the latest value, preserve ordered history, choose between sources or follow corrections to individual facts. Different views can use the same source differently.
