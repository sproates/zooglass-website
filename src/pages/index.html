ZooGlass

ZooGlass maintains live views from events produced by independent systems. Your application can subscribe to a view, receive its current state and follow subsequent changes.

The problem it solves

When events arrive late, arrive twice or go missing, the last message received may tell only part of the story. Which value should an application show? What should a returning subscriber see after missing several updates?

You configure which sources contribute to each field and choose how it should handle updates. ZooGlass applies the configured strategy for each field as events arrive, so each application can use the resulting view without implementing those rules itself.

One strategy keeps the value with the highest sequence number. Another keeps a history in sequence order. The same late event can fill a gap in the history while leaving the current value intact.

You can test those decisions with the Workbench Scenario Simulator. Set up a sequence of events and disconnects, then check both the view ZooGlass maintains and the snapshot a subscriber receives when it reconnects.
