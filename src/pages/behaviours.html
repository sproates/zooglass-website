The behaviour is part of the definition

Behaviours

The same event can mean different things to different views. Choose the rule for each field, then let ZooGlass apply it consistently.

When delivery is imperfect

An older event arrives last

latestBySequence keeps the value with the highest sequence number. An older report cannot replace it.

historyBySequence can use that same report to fill a gap in ordered history. arrival is available when receipt order is the intended rule.

A source retries an event

ZooGlass gives each publication an identity. When a source retries the same publication within the retention window, ZooGlass acknowledges it as a duplicate. The acknowledgement includes the original version and the recorded outcomes for the affected views. Their state stays unchanged. ZooGlass rejects a retry that reuses the identity with different content.

Identity retention is bounded. This is a defined retry window, not an unlimited deduplication archive.

Two sources disagree

Configure source priority for a multi-input field. ZooGlass chooses from the available contributions using that priority, without comparing sequence numbers from unrelated sources.

Sources can also contribute to separate fields, with their keys mapped to the same view entity.

Part of the view is missing

Required-field publication can wait for the contributions a view needs. A partial set of inputs does not have to become a published view.

Reports are missing

When a source declares contiguous sequences for each entity, a jump exposes a provisional gap. A watermark confirms which reports are still missing through that point. ZooGlass keeps this status alongside the accepted values.

Each field can accept late reports or reject reports behind the watermark. A late arrival can fill a gap without replacing a newer value; ZooGlass also records when it breaks the source’s watermark promise.

A source goes quiet

Receipt-age freshness distinguishes an ageing value from a fresh contribution while retaining the last known value.

Freshness describes age, not completeness. A stale contribution does not automatically change the configured source priority.

When the facts themselves change

Corrections and withdrawals

With activeFacts, each fact has a stable birth sequence and its own revision. Choose latestFactRevision to follow corrections and withdrawals, or firstFact to preserve the first accepted create.

A revision received before its create is rejected as unknownFact. The source can retry after the create arrives.

Totals that follow corrections

Use sumActiveFacts to total a numeric field across retained active facts. A correction changes the contribution; a withdrawal removes it. The total follows the configured revision policy, so the application does not need its own correction arithmetic.

A deliberate retention boundary

Fact collections have a configured capacity. Withdrawals leave tombstones; explicit retirement removes older records and advances a floor that prevents their reintroduction.

Each field owns its retained window. This is the current retained collection, not an unlimited audit history.

Configuration selects real strategy code.

Strategies are named modules in ZooGlass. Configuration selects them; runtime processing uses them. The application does not have to reproduce their decisions.
