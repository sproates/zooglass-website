Evidence behind the behaviour

Verification

A useful contract must hold when delivery fails, when a process stops and when a source tries again.

Check the state an application receives.

Several levels of evidence

Focused strategy tests check individual decisions. Service tests exercise real interfaces. Crash tests start a separate ZooGlass process, terminate it at controlled boundaries and inspect the recovered result.

Workbench adds controlled delivery scenarios. The vehicle demo makes some of their effects visible; it is not the only evidence for the core.

What the checks ask

Did a lost acknowledgement repeat the effect?

Stop the service before commit, after commit but before acknowledgement, and after acknowledgement. Restart it, retry the publication and check the durable view and receipt.

Database crash recovery tests ↗

Did a withdrawn fact come back?

Crash around fact retraction and retirement commits. Check that recovered projections, tombstones, retirement floors and retry outcomes agree.

Fact crash tests ↗

Does the real interface honour the rule?

Publish facts and retirement controls through WebSockets, then inspect HTTP snapshots. Exercise corrections, withdrawals and rejection outcomes at the service boundary.

Fact service tests ↗

Is ageing still meaningful after recovery?

Check receipt-age state through restart and clock changes, including the distinction between a recovered value and a newly received contribution.

Freshness recovery tests ↗

Can invalid state become a ready service?

Recovery tests check persisted state and configuration compatibility. Invalid recovery must fail rather than expose a partially recovered view.

Storage recovery tests ↗

Do different views retain different facts?

Exercise independent revision policies, bounded collections and explicit retirement. Check the results together with publication and freshness behaviour.

Fact composition tests ↗

Evidence links are pinned to main revision 0903ad8. Crash checks use the real database driver and process termination; they do not simulate hardware power loss.
